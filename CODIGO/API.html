1. Clases desarrolladas para Realizar Validaciones

Componentes de la capa de servicios encargados del procesamiento y ejecución de las reglas físicas, de tipo de dato y restricciones atómicas sobre los campos del formulario.

Clase: Validations

Implementa las funciones estáticas de validación atómica directamente contra los elementos del DOM.

Método: isRequired

Descripción: Comprueba si un elemento HTML requerido contiene un valor que no esté vacío.

Parámetros de Entrada:
Nombre Tipo de dato Descripción
elementId String El identificador único (ID) del elemento input en el DOM.
Información Devuelta:
Nombre Tipo de dato Descripción
result Boolean | String Retorna true si el campo tiene datos; o el string 'Campo requerido' si está vacío.

Método: isInteger

Descripción: Evalúa si el valor cargado en el input es un número entero válido mediante expresiones regulares.

Parámetros de Entrada:
Nombre Tipo de dato Descripción
elementId String El identificador único (ID) del elemento input a analizar.
Información Devuelta:
Nombre Tipo de dato Descripción
result Boolean | String Retorna true si está vacío o es entero; o el string 'Solo se permiten dígitos' si falla el formato.

Clase: ValidateFieldsForm

Instancia campos individuales del formulario encapsulando sus definiciones, reglas operativas y adaptando los formatos de validación.

Método: validateField

Descripción: Ejecuta un control condicional en bucle que mapea las reglas de la instancia y delega en el motor estático de Validations.

Parámetros de Entrada:
Nombre Tipo de dato Descripción
ruleName String Nombre identificativo de la regla de validación a ejecutar (ej. 'minSize', 'maxSize', 'format').
params Object Parámetros adicionales requeridos para la regla (longitud, expresiones o tipos de archivo).
Información Devuelta:
Nombre Tipo de dato Descripción
status Boolean | String El resultado procedente de la invocación de la función estática de validación correspondiente.

Diagrama de Flujo del Proceso a Nivel de Código (Validaciones):

Inicio

Orquestación

ValidateFieldsForm procesa las directivas del campo y dispara sus reglas.

➔

Bifurcación Condicional

Un bloque switch(rule) redirige el flujo al método estático adecuado de la clase de servicios.

➔

Consulta DOM

Validations.isRequired() o isInteger() extraen el valor mediante document.getElementById().

➔
Fin

Evaluación

Retorna true si supera las restricciones o un literal de cadena con el mensaje semántico de error.

2. Clases desarrolladas para los Test de Atributos

Componentes dedicados a la automatización de las pruebas físicas integrales del modelo, auditando el formato de las definiciones y procesando las matrices de prueba.

Clase: TestForm

Se encarga de ejecutar el análisis estructural completo y la batería iterativa de pruebas sobre los atributos.

Método: analyzeStructure

Descripción: Audita la variable de configuración estructural para garantizar que sea un objeto existente y válido.

Parámetros de Entrada:

Ninguno (Lee las propiedades locales asignadas en el constructor: this.estructura).

Información Devuelta:
Nombre Tipo de dato Descripción
analysis Object Objeto de control que devuelve un estado binario y el literal del error encontrado: { valid: Boolean, error: String }.

Método: executeAllTests

Descripción: Ejecuta el procesamiento iterativo en un bucle que recorre la matriz completa de pruebas contrastando los resultados.

Parámetros de Entrada:

Ninguno.

Información Devuelta:
Nombre Tipo de dato Descripción
resultsArray Array (of Objects) Matriz con objetos detallados de cada iteración conteniendo: número de prueba, campo, esperado, obtenido y estatus (OK/FAIL).

Clase Auxiliar de Inicialización: Gestor

Componente que actúa como pasarela unificada, validando los entornos globales del navegador antes de ceder el control al motor de tests.

Método: validateEntityFiles

Descripción: Comprueba con el operador reflexivo typeof window[...] que las variables requeridas en los scripts estén correctamente instanciadas en la ventana global.

Parámetros de Entrada:

Ninguno.

Información Devuelta:
Nombre Tipo de dato Descripción
void Undefined No tiene retorno explícito. Si falla, acumula los errores y detiene la aplicación interrumpiendo el flujo mediante un throw new Error.

Diagrama de Flujo del Proceso a Nivel de Código (Tests de Atributos):

1

Auditoría de Entorno

Gestor.validateEntityFiles() comprueba las colecciones estructurales de window en memoria.

➔

2: Análisis Formal

TestForm.showWindow() invoca secuencialmente a analyzeStructure() y a los evaluadores de definiciones.

➔

3: Bucle Iterativo

executeAllTests() mapea la matriz de datos de prueba y computa las aserciones lógicas frente al valor esperado.

➔
UI

4: Inyección DOM

displayResults() monta de manera dinámica el árbol modal y dibuja la tabla pintando las filas según las clases semánticas.

3. Clases desarrolladas para Comprobar el Submit

Módulos encargados de simular y certificar el comportamiento y respuestas del sistema frente a eventos de persistencia u operaciones de guardado de formularios de la entidad.

Clase: TestSubmit

Modela el motor de análisis agrupado de peticiones CRUD simulando la sumisión completa de datos de campos del formulario.

Método: analyzeAllActions

Descripción: Extrae mediante la estructura indexada Set los tipos únicos de acciones CRUD que componen el set de pruebas.

Parámetros de Entrada:

Ninguno (Consume los datos almacenados de forma interna en el miembro this.testSubmitData).

Información Devuelta:
Nombre Tipo de dato Descripción
groupAnalyses Object Diccionario indexado por acciones (ADD, EDIT, SEARCH) que acumula los balances y contadores de aciertos del submit.

Método: showWindow

Descripción: Método coordinador principal del submit. Valida la existencia del array de datos o interrumpe el flujo delegando el error visual.

Parámetros de Entrada:

Ninguno.

Información Devuelta:
Nombre Tipo de dato Descripción
void Undefined Genera, inyecta y visualiza la estructura del modal interactivo sobre el document.body.

Diagrama de Flujo del Proceso a Nivel de Código (Comprobación de Submit):

Inicio

Filtro de Datos

showWindow() evalúa el estado del array de sumisión. Si viene vacío, aborta la ejecución llamando a showError().

➔

Agrupación Dinámica

analyzeAllActions() itera aislando las acciones en una estructura Set para independizar los casos.

➔

Evaluación de Bloque

Se evalúa el conjunto completo de atributos requeridos simulando el envío del formulario bajo el contexto operativo de la acción.

➔
Fin

Renderizado

displayResults() segmenta la vista modal por operaciones CRUD e inyecta las tablas analíticas de éxito/error del submit.
